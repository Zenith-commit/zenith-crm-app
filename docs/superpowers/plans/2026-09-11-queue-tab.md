# Queue Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add admin/office-only "queues" (named job-organization folders, independent of `job_status`) with create/rename/delete management, a job-to-queue assignment picker on `JobDetail`, and a queue column/filter on the Jobs list. Technicians get zero access anywhere.

**Architecture:** A new `queues` table (RLS: admin `for all`, office full CRUD including delete — non-destructive here since deleting a queue never deletes a job) plus a nullable `jobs.queue_id` FK with `on delete set null`, so deleting a queue only unassigns its jobs. A shared `useQueues()` hook backs three consumers: a new `/queues` management page, a queue filter/column on the existing Jobs list, and a queue picker on `JobDetail`'s Details tab. No new routes beyond `/queues`, no new dependencies, no changes to `job_status` or any technician-facing code/RPC.

**Tech Stack:** React + Vite, Supabase (Postgres RLS), no automated JS test framework exists in this repo — verification follows this project's established pattern of live RLS checks run manually in the Supabase SQL Editor, plus manual browser verification for the frontend.

**Spec:** `docs/superpowers/specs/2026-09-11-queue-tab-design.md`

## Global Constraints

- Queues are fully independent of `job_status` (`Quote → Work Order → Scheduled → Completed`) — do not touch `public.job_status` or any status logic.
- Technicians have zero access to queues, everywhere — no RLS policy on `queues`, no queue UI rendered for them, no changes to `get_my_jobs()` or any other technician-facing RPC.
- Assignment is manual only — no automatic status-based or event-based queue assignment logic.
- No bulk job reassignment UI — per-job only, matching how `assigned_to` already works. This app has no existing bulk-action UI to extend.
- `queues` has no `active` flag (deleting is non-destructive to jobs, so hard delete is correct) and no `unique` constraint on `name`.
- Deleting a queue must never delete or cascade-delete a job — `jobs.queue_id` is `on delete set null`.
- The `JobDetail` queue picker is a plain flat `<select>` (confirmed assumption: queue counts are expected to stay small, unlike the materials catalog or repeat-client addresses) — do not build a searchable combobox for it.
- This project has no Supabase CLI/service-role access configured in this environment — every SQL file must be run by the human via the Supabase Dashboard SQL Editor, not executed directly by the agent.
- No new npm dependencies anywhere in this plan.
- No route guards exist anywhere in this app — do not introduce one for `/queues`.

**Files:**

**Interfaces:**

  id uuid primary key default gen_random_uuid(),
  name text not null,
  created_by uuid references public.users(id),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()

- [x] **Step 1: Write `useQueues.js`**

```js
import { useCallback, useEffect, useState } from 'react'
import { supabase } from '../lib/supabaseClient'

export function useQueues() {
  const [queues, setQueues] = useState([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState(null)

  const reload = useCallback(async () => {
    setLoading(true)
    const { data, error } = await supabase
      .from('queues')
      .select('id, name, created_at')
      .order('name', { ascending: true })

    if (error) setError(error)
    else setQueues(data)
    setLoading(false)
  }, [])

  useEffect(() => {
    reload()
  }, [reload])

  async function create(name) {
    const { data: { user } } = await supabase.auth.getUser()
    const { error } = await supabase.from('queues').insert({ name, created_by: user.id })
    if (error) return { error }
    await reload()
    return { error: null }
  }

  async function rename(id, name) {
    const { error } = await supabase.from('queues').update({ name }).eq('id', id)
    if (error) return { error }
    await reload()
    return { error: null }
  }

  async function countJobsInQueue(id) {
    const { count, error } = await supabase
      .from('jobs')
      .select('id', { count: 'exact', head: true })
      .eq('queue_id', id)
    if (error) throw error
    return count ?? 0
  }

  async function remove(id) {
    const { error } = await supabase.from('queues').delete().eq('id', id)
    if (error) return { error }
    await reload()
    return { error: null }
  }

  return { queues, loading, error, reload, create, rename, countJobsInQueue, remove }
}
```

- [x] **Step 2: Write `QueueList.jsx`**

```jsx
import { useState } from 'react'
import { useQueues } from '../hooks/useQueues'

export default function QueueList() {
  const { queues, loading, error, create, rename, countJobsInQueue, remove } = useQueues()
  const [newName, setNewName] = useState('')
  const [creating, setCreating] = useState(false)
  const [formError, setFormError] = useState(null)
  const [editingId, setEditingId] = useState(null)
  const [editingName, setEditingName] = useState('')

  if (loading) return <p>Loading...</p>
  if (error) return <p role="alert">Could not load queues: {error.message}</p>

  async function handleCreate(e) {
    e.preventDefault()
    if (!newName.trim()) return
    setCreating(true)
    setFormError(null)
    const { error } = await create(newName.trim())
    setCreating(false)
    if (error) {
      setFormError(error.message)
      return
    }
    setNewName('')
  }

  function startRename(queue) {
    setEditingId(queue.id)
    setEditingName(queue.name)
    setFormError(null)
  }

  async function handleRename(id) {
    if (!editingName.trim()) return
    const { error } = await rename(id, editingName.trim())
    if (error) {
      setFormError(error.message)
      return
    }
    setEditingId(null)
  }

  async function handleDelete(queue) {
    const count = await countJobsInQueue(queue.id)
    const message = count > 0
      ? `This queue has ${count} job${count === 1 ? '' : 's'} — they'll become unqueued. Delete anyway?`
      : 'Delete this queue?'
    if (!window.confirm(message)) return
    const { error } = await remove(queue.id)
    if (error) setFormError(error.message)
  }

  return (
    <div>
      <h1>Queues</h1>
      <form onSubmit={handleCreate}>
        <label>
          New queue name
          <input value={newName} onChange={(e) => setNewName(e.target.value)} />
        </label>
        <button className="btn-primary" type="submit" disabled={creating}>
          {creating ? 'Adding...' : 'Add Queue'}
        </button>
      </form>
      {formError && <p role="alert">{formError}</p>}
      <table>
        <thead>
          <tr>
            <th>Name</th>
            <th></th>
          </tr>
        </thead>
        <tbody>
          {queues.map((queue) => (
            <tr key={queue.id}>
              <td>
                {editingId === queue.id ? (
                  <input value={editingName} onChange={(e) => setEditingName(e.target.value)} />
                ) : (
                  queue.name
                )}
              </td>
              <td>
                {editingId === queue.id ? (
                  <>
                    <button className="btn-primary" type="button" onClick={() => handleRename(queue.id)}>
                      Save
                    </button>
                    <button type="button" onClick={() => setEditingId(null)}>Cancel</button>
                  </>
                ) : (
                  <>
                    <button type="button" onClick={() => startRename(queue)}>Rename</button>
                    <button type="button" onClick={() => handleDelete(queue)}>Delete</button>
                  </>
                )}
              </td>
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  )
}
```
